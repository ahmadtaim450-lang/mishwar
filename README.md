# مشوار 🚗
### رحلات آمنة بين المدن السورية مع سائقين موثّقين

**مشوار** تطبيق سوري لحجز مقاعد بالسيارات المسافرة بين المدن. **بس السائقين الموثّقين بينشروا رحلات:** كل سائق بيقدّم أوراقو (هوية، شهادة سواقة، لا حكم عليه، أوراق السيارة)، وبيعمل مقابلة وفحص سيارة بنقطة مشوار قبل ما يتفعّل. الراكب بيحجز مقعدو، وبيتأكد من السائق برقم السيارة ورمز رحلة، وأهلو بيتابعوا موقعو مباشرة.

| | الرابط |
|---|---|
| تطبيق أندرويد (APK) | قسم **[Releases](../../releases)**، الملف اللي اسمو فيه `arm64-v8a` |
| نسخة الآيفون (ويب) | https://ahmadtaim450-lang.github.io/mishwar/ |
| صفحة متابعة الأهل | `https://ahmadtaim450-lang.github.io/mishwar/track/?t=…` (بتنبعت من التطبيق) |
| لوحة الإدارة | https://ahmadtaim450-lang.github.io/mishwar/admin/ |

> بدون مفاتيح Supabase، التطبيق بيشتغل **بوضع تجريبي** واضح (شريط أصفر "نسخة تجريبية") وكل البيانات بالذاكرة. أول ما تنضاف المفاتيح بيصير حقيقي بلا أي تعديل بالكود.

## 🏗️ البنية

```
┌────────────── Flutter (أندرويد + ويب للآيفون) ──────────────┐
│ الشاشات  ─►  Store (حالة التطبيق)  ─►  Backend (واجهة)      │
│                                    ├─ SupabaseBackend (حقيقي) │
│                                    └─ DemoBackend (تجريبي)    │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTPS (مفتاح anon عام + JWT المستخدم)
┌──────────────────────────────▼───────────────────────────────┐
│ Supabase                                                      │
│  Auth: دخول برقم الموبايل ورمز SMS                            │
│  Postgres: جداول محمية بـ RLS + دوال RPC لكل عملية حساسة       │
│  Storage: أوراق السائقين (خاص)، الصور الشخصية (عام)           │
│  Realtime: الرسائل والإشعارات                                 │
│  Edge Functions: push (FCM) · admin-delete-user                │
└──────────────────────────────┬───────────────────────────────┘
        صفحات ويب ثابتة (GitHub Pages): متابعة الأهل · لوحة الإدارة
```

**قاعدة أساسية:** التطبيق ما بيكتب على الجداول مباشرة. كل عملية (حجز، موافقة، نشر، تقييم، بلاغ...) بتمرق بدالة RPC بالسيرفر بتتحقق من الهوية والصلاحية والمدخلات وبتقفل الصفوف لتمنع الحجز المزدوج. الأخطاء بترجع كرموز ثابتة (`NOT_ENOUGH_SEATS`) والتطبيق بيترجمها لرسائل عربية (`lib/core/errors.dart`).

### هيكل المشروع
```
lib/
  core/      الإعدادات (config) · الأخطاء الموحّدة · الثيم · الإشعارات (push)
  data/      Store · Backend (الواجهة) · SupabaseBackend · DemoBackend · النماذج · المدن والمسافات
  screens/   كل الشاشات (الدخول، الرئيسية، البحث، الرحلة، الحجز، رحلاتي، النشر، السائق، الرسائل، الحساب)
  widgets/   مكوّنات مشتركة · خريطة الوجهات · خريطة الرحلة · خريطة سوريا ثلاثية الأبعاد
supabase/
  migrations/  قاعدة البيانات (الجداول، RLS، الدوال، التخزين، الإشعارات)
  functions/   push (FCM) · admin-delete-user
  tests/       اختبارات SQL · اختبار شامل (e2e) على Supabase حقيقي
site/          صفحة متابعة الأهل · لوحة الإدارة · مكتبات (Leaflet، supabase-js)

.github/workflows/  بناء APK · نسخة الويب · اختبارات الباكند · نشر قاعدة البيانات
```

## ✨ الميزات

**للراكب:** دخول برقم الموبايل ورمز SMS · بحث بالكتابة مع تصحيح الأخطاء (حماه ← حماة) · خريطة وجهات تفاعلية · **الحجز على جزء من الطريق** (رحلة اللاذقية ← دمشق بتطلع لمين رايح من طرطوس لحمص، بسعر ووقت حسب المسافة) · نتائج حسب الجنس والمقاعد · حجز فوري أو بموافقة · حجز عائلي · تذكرة فيها رقم السيارة ورمز الرحلة (بعد التأكيد) · محادثة مع السائق · تتبع GPS حقيقي · رابط متابعة مباشرة للأهل · زر طوارئ بيبعت الموقع · صورة شخصية · تقييم وبلاغ · إشعارات.

**للسائق:** طلب انضمام بـ5 خطوات مع تصوير الأوراق ورفعها · متابعة حالة الطلب · نشر رحلة بسعر مقترح حسب المسافة والوقفات على الطريق · قبول ورفض الطلبات (مع وين بيطلع وبينزل كل راكب وتقييمو) · تقييم الركاب بعد الرحلة · شاشة الرحلة بتشارك موقعو كل 20 ثانية (وبتكمّل والشاشة مطفية) · بدء وإنهاء الرحلة · إلغاء الرحلة مع إبلاغ الركاب.

**للإدارة:** نظرة عامة بالأرقام وأكتر الطرق · مراجعة الطلبات مع الأوراق (روابط مؤقتة) · تحديد مقابلة · تفعيل أو رفض · الرحلات القريبة وحجوزاتها · البلاغات وإيقاف السائقين · طلبات حذف الحساب (حذف نهائي آمن) · سجل العمليات.

**تلقائياً بالسيرفر (كل نص ساعة):** الرحلات اللي السائق نسي يسكّرها بتخلص بعد 12 ساعة من الوصول والركاب بيوصلهن طلب تقييم · الطلبات اللي ما انرد عليها لحد الانطلاق بتنلغى · تنظيف المواقع الحية والروابط المنتهية والإشعارات القديمة.

**مبادئ:** محايد لكل السوريين · صور محتشمة بلا اختلاط · رحلات نسائية بسائقات بس · العائلات مع بعض · تفضيل أغاني أو بلا أغاني.

## 🔐 الأمان والصلاحيات

- **RLS على كل الجداول**، وكل الكتابة الحساسة عن طريق دوال `security definer` بتتحقق من `auth.uid()`.
- **الأدوار (RBAC):** `user` · `moderator` · `admin`، وحالة السائق (`none → reviewing → interview → approved`، و`rejected`/`suspended`). الدور ما بيتغيّر من التطبيق أبداً (صلاحيات أعمدة).
- **الخصوصية:** رقم الموبايل ورقم السيارة ورمز الرحلة ما بيظهروا إلا بعد تأكيد الحجز، وللطرفين بس. أوراق السائق بمجلد خاص (`{uid}/…`) ما بيقراه غير صاحبو والإدارة.
- **منع التلاعب:** قفل صف الرحلة وقت الحجز (`FOR UPDATE`) · حجز فعّال واحد لكل راكب بالرحلة · حدود معدّل (10 طلبات حجز بالساعة، 6 رحلات باليوم، 5 بلاغات باليوم) · قواعد الجنس بالسيرفر مو بالواجهة بس.
- **المدخلات:** قيود CHECK بكل الجداول + تنظيف النصوص (`_clean`) + تحقق بالتطبيق. صفحات الويب بتعرض البيانات كنص (`textContent`) لمنع XSS.
- **الأسرار:** ما في أي سر بالتطبيق أو الصفحات. مفتاح `anon` عام بطبيعته. مفتاح `service_role` وحساب FCM بالسيرفر بس.
- **السجل:** كل عملية مهمة بتنكتب بـ `audit_log` (بدون معلومات حساسة)، والإدارة بتشوفو.

## 💻 التشغيل المحلي

```bash
# 1) التطبيق بالوضع التجريبي (بلا سيرفر)
flutter pub get
flutter run

# 2) مع Supabase محلي (بدو Docker)
supabase start                       # بيطبّق كل الـ migrations
supabase status -o env               # بيعطيك API_URL و ANON_KEY
flutter run --dart-define=SUPABASE_URL=http://10.0.2.2:54321 --dart-define=SUPABASE_ANON_KEY=<ANON_KEY>
```
بالمحلي، الأرقام `963900000001` و `963900000002` بتقبل الرمز `123456` بلا SMS (`supabase/config.toml`).

> ملاحظة: الصور (الرسومات) والخط بيتنزّلوا وقت البناء بـ GitHub Actions من `assets/manifest.txt`.

## 🚀 النشر للإنتاج خطوة بخطوة

1. **مشروع Supabase:** اعمل مشروع على supabase.com (المنطقة الأقرب: Frankfurt).
2. **قاعدة البيانات:** ضيف بأسرار GitHub (Settings › Secrets › Actions):
   `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`, `SUPABASE_DB_PASSWORD`. بعدها كل تعديل بـ `supabase/migrations` بينشر لحالو (workflow: Deploy database)، أو يدوياً: `supabase link --project-ref … && supabase db push`.
3. **الدخول بالموبايل:** من لوحة Supabase › Authentication › Providers › Phone: فعّل الموبايل واختار مزوّد SMS (Twilio / Vonage / MessageBird) وحط مفاتيحو. تأكد إنو المزوّد بيوصّل لأرقام سوريا (+963).
4. **ربط التطبيق:** ضيف بأسرار GitHub `SUPABASE_URL` و `SUPABASE_ANON_KEY` (من Project settings › API). أي بناء جديد للـ APK والويب بيصير حقيقي.
5. **حساب المدير:** من Authentication › Users اعمل مستخدم بإيميل وكلمة سر، وبعدين من SQL Editor:
   ```sql
   update public.profiles set role = 'admin', full_name = 'اسمك' where id = '<user-id>';
   ```
6. **دوال السيرفر:**
   ```bash
   supabase functions deploy push --no-verify-jwt
   supabase functions deploy admin-delete-user
   supabase secrets set PUSH_SECRET=<كلمة-سر-طويلة> ADMIN_ORIGINS=https://ahmadtaim450-lang.github.io
   ```
7. **إشعارات الموبايل (FCM):** اعمل مشروع Firebase وضيف تطبيق أندرويد باسم الحزمة `com.mishwar.mishwar`.
   - بأسرار GitHub: `FIREBASE_API_KEY`, `FIREBASE_APP_ID`, `FIREBASE_SENDER_ID`, `FIREBASE_PROJECT_ID`.
   - حساب الخدمة (Service account JSON): `supabase secrets set FCM_SERVICE_ACCOUNT='<json بسطر واحد>'`.
   - بالـ SQL Editor (لحتى قاعدة البيانات تنادي دالة push):
     ```sql
     create extension if not exists pg_net;
     select vault.create_secret('https://<project-ref>.supabase.co/functions/v1', 'functions_url');
     select vault.create_secret('<نفس PUSH_SECRET>', 'push_secret');
     ```
8. **نسخة الويب ولوحة الإدارة:** GitHub Pages (Source: GitHub Actions) مفعّل. الصفحات بتاخد المفاتيح من نفس الأسرار وقت النشر.

## 📋 المهام المتبقية

**بتحتاج منك (مفاتيح أو قرارات):**
- مزوّد SMS بيوصّل لسوريا وتجربتو على أرقام حقيقية.
- مشروع Firebase للإشعارات.
- تحديد نقاط المقابلة الفعلية بكل مدينة (العناوين بتنكتب من لوحة الإدارة مع كل موعد).
- مراجعة نصوص سياسة الخصوصية والشروط من محامي قبل الإطلاق.

**جاهز بالكود بس لازم يتجرّب على جهاز حقيقي:**
- وصول رسائل SMS لأرقام سورية (بيعتمد على المزوّد).
- إشعارات FCM على الموبايل (الكود والدالة جاهزين، بدن مفاتيح Firebase).
- التتبع والشاشة مطفية (خدمة أندرويد ظاهرة بإشعار، ما انجرّبت على جهاز).
- الكاميرا لتصوير الأوراق والصورة الشخصية.

**تطوير لاحق:**
- نسخة iOS أصلية (حالياً نسخة ويب تشتغل كتطبيق على الآيفون، بلا إشعارات push).
- المقعد بالحجز على جزء من الطريق بينحسب لكل الرحلة (أبسط للسائق)؛ لاحقاً ممكن نحسبو حسب الأجزاء.
- ربط سجل الأخطاء بخدمة مراقبة (مثلاً Sentry) من `lib/core/log.dart`.
- الدفع الإلكتروني (حالياً كاش للسائق).
